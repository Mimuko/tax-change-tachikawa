# 要件定義 — 税金で、何が変わった？（仮称）

## 依頼の要約

立川市の一般市民が、介護に関する公開行政データから「自分の街で何が変わったか」を視覚的に理解し、自分の疑問を持てるWebサービスを作る。

## 目的・背景

- 出発点は「介護の需要がある一方で、介護職の賃金や供給体制はどう変化しているのか」という疑問。
- 行政支出の使途だけでなく、その期間に社会側で観測された変化を市民が追えるようにする。
- 行政・政策の評価や因果推論は行わず、公開データの増減・差・関係性を再編集して提示する。

## 本質課題

行政資料は年度・制度・資料単位に分散し、定義や単位も異なるため、一般市民が数年間の変化と根拠を短時間で把握しにくい。必要なのはデータ量の多いダッシュボードではなく、意味のある順序で変化を理解でき、原典まで遡れる情報体験である。

## コンセプト

- メッセージ: **「税金はどこへ行った？」ではなく「税金で、何が変わった？」**
- UX上の入口: **「自分の街はどう変わった？」**
- サイトが結論を与えるのではなく、ユーザー自身が変化に気づき、疑問を持てる状態を作る。

## 対象・前提・制約

| 項目 | MVP |
|---|---|
| 自治体 | 東京都立川市 |
| テーマ | 介護 |
| 期間 | 原則、確定済み実績の直近5年度（指標ごとに利用可能期間を明記） |

## 情報階層

1. 何が変わった？
2. どの程度変わった？
3. なぜそう見える？
4. 内訳は？
5. 具体的な値は？
6. その根拠は？

第一階層では数値カードや表を大量配置せず、方向・量・関係性を中心に伝える。具体値、定義、加工方法、原典は展開可能な第二階層以降に置く。

## デザイン方針

- 参照デザイン（配色・余白・タイポグラフィ・導線・終端セクション）を基準とする。ローカルのデザインアーカイブはリポジトリに含めない。
- 生成物内の仮値・仮データ注記は採用せず、検証済みの実データと出典表示へ置き換える。
- 生成物の指標別独立表示は採用せず、確定済みの「同一ビジュアライゼーションへ系列を累積する」構造を維持する。
- 暖色系の紙面背景、深緑の本文色、橙色のアクセント、明朝系見出しを基本とする。
- 装飾よりも可読性、データの区別、キーボード操作、モバイル表示を優先する。

## スクロール体験

- トップ画面では指標ごとのカード型・独立グラフを使用しない。
- デスクトップでは説明文をスクロールさせ、同一の固定ビジュアライゼーションへ系列を順次追加する。
- 単位の異なる系列は最初の年度を100とする変化指数で同じ座標へ置き、実数値と単位は凡例・詳細表で示す。
- 一度登場した系列は後続ステップでも残し、需要・認定・給付・保険料の変化を累積的に比較できるようにする。
- スクロール位置だけに依存せず、全ステップを文書順に読み上げ可能にする。モバイルではビジュアライゼーションを各説明の前後で追従可能な範囲に縮小する。
- `prefers-reduced-motion` では線の描画アニメーションを行わず、状態を即時反映する。

## 業務・コンテンツ要件（Must）

- 「介護を必要とする人」「サービスの受け皿」「支える人」「待遇」「行政支出・市民負担」の順に物語を構成する。
- 観測できる事実だけを示し、政策評価や因果関係を断定しない。
- 各指標に前年比と5年前比を表示可能にする。比較不能は理由付きで表示する。
- 件数は必要に応じ人口、第1号被保険者数等で正規化し、分母・基準日を併記する。
- 欠損を0や推測値で補完しない。
- 「データなし」「比較不可」「定義変更あり」「取得失敗」「原典側で未公開」を区別する。
- 各値に出典名、年度、取得日、原典URL、定義、単位、元値、加工値、加工方法を紐付ける。
- 内部の行政上の正式分類と、市民向け表示分類を別レイヤーで保持する。
- 次の注意書きを掲載する: 「本サイトは公開されている行政データを独自に収集・整理・可視化するものです。原典の数値・定義等に関するお問い合わせは、各データの掲載元へお願いいたします。」
- URL共有またはWeb Share APIで気づきを共有できる。

## Act 3 データ可用性（支える人・待遇）

`dashboard.json` の `place` と系列の有無で UI を分岐する。判定は `resolveSupportAvailability` が正本。

| 条件 | Gap Interlude | Act 3 | GeographyChip |
|---|---|---|---|
| 市区町村の賃金または職員数に比較可能な時系列（2点以上） | 表示しない | 市区町村スコープで表示 | `municipality` |
| 市区町村系列なし・都道府県参考（`reference.prefecture`, `referenceOnly: true`）のみ | 表示する | 都道府県参考スコープで表示 | `prefecture-ref` |
| いずれも比較不可 | — | Act 3 非表示 | — |

- 都道府県参考値を市区町村の実績として扱わない。
- 詳細アコーディオン・振り返り（Act 5）も同じ可用性に追随する。
- 自治体ラベルは `config/*.json` → `place.municipalityLabel` / `place.prefectureLabel` から解決する。

## 表現ルール

- 使用する: 増減、変化率、差、目標値と実績値の差、↑／→／↓。
- 使用しない: 「悪化」「有効活用」「低すぎる」「失敗」などの価値判断。
- 初期実装では「増加・減少・横ばい」の独自閾値を設けない。0は「変化なし」、正負は方向として表示する。
- 因果を示す接続表現を避け、複数系列は「同じ期間に観測された変化」として提示する。

## 技術要件

- Next.js / TypeScript を基本とする。
- データ処理は `source -> parse -> normalize -> validated JSON -> UI` とする。
- DBは使用せず、将来RDBへ移行可能な行指向の指標構造にする。
- グラフは第一候補をObservable Plotとし、SSR互換性やバンドル量を検証する。
- モバイル優先、主要ブラウザ最新版、SEO、OGP、Lighthouseを考慮する。
- 更新処理は非ゼロ終了、構造検証、ログ保存に対応し、ユーザー画面へ技術的エラーを露出しない。
- 第三者が `install -> fetch -> normalize -> build` の手順を再現できる。
- 取得、定義、加工、表示ロジックをGitHub上で確認できる状態にする。
- 立川市固有のURL・自治体コード・出典情報を設定へ分離し、共通処理へ埋め込まない。
- 秘密情報はコミットせず、`.env` にのみ置く。必要な変数名は docs / スクリプト先頭コメントに記載する。

## オープンソース・GitHub公開要件

- 本プロジェクトは公開GitHubリポジトリとして運用する。
- 目的は、データ処理の透明性、第三者検証、他自治体展開、Civic Tech / GovTechでの再利用性の確保とする。
- `README.md`、`LICENSE`、`CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md`、`docs/`、`src/`、`scripts/`、`data/` を必須構成とする。
- Issueテンプレートは「不具合」「データ追加・修正」「機能・指標・自治体提案」を区別する。
- PRでは変更内容、理由、根拠となるデータソース、表示結果への影響、検証結果を記載する。
- 表示結果だけでなく、取得・定義・加工・表示までの過程を公開成果物とする。

## ライセンス要件

- ソースコードは依存ライブラリとの整合を確認したうえでMIT Licenseを採用する。
- `package.json` の `private: true` はnpmへの誤公開防止であり、GitHubリポジトリの非公開指定ではない。
- 原典データ、rawデータ、processedデータにソースコードのMIT Licenseを適用しない。
- データごとに出典、原ライセンス、クレジット要否、加工可否、再配布可否を記録する。
- 原典のライセンスが未確認のデータは、確認完了までGit管理・再配布の対象にしない。

## アクセシビリティ（Must）

- 色だけで増減を区別しない。
- 全グラフに要約文とデータ表への到達手段を用意する。
- キーボード操作、意味のある見出し構造、フォーカス表示を保証する。
- WCAG 2.2 AA相当のコントラストを目標にする。
- `prefers-reduced-motion` では装飾的な動きを停止する。

## 非要件（MVP Out）

- 全国・他自治体比較
- 将来予測
- 因果推論
- 個人の納税額試算
- CMS・認証・DB・管理画面
- 行政施策の採点、ランキング、推奨

## Acceptance Criteria

1. 初見ユーザーが30秒以内に、立川市の介護について増減・停滞を3点以上説明できる。
2. 閲覧後、気になる点・疑問・自治体に確認したいことを1つ以上言語化できる。
3. 気づいた内容をSNS等で共有できる。
4. 具体値を暗記しなくても、直近数年間の変化を説明できる。
5. 表示値から定義・加工方法・原典URLまで追跡できる。
6. 欠損・比較不能を0として誤表示しない。
7. スクロールを進めると、同一グラフ上で4系列が順次累積し、最終状態で全系列を比較できる。
